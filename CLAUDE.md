# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Git

Commit straight to the current branch (usually `main`). Don't create a new branch unless asked.

## What this is

MySelf is a "personal OS" SwiftUI app: dashboard, TODOs, University (classes, syllabus, assignments, exams), Office Tasks, Job Study, Product Dev (Kanban), Workout, Notes, and Book Notes. The UI is a native port of a Claude Design HTML/React prototype (`MySelf.zip`; the macOS variant is `MySelf macOS.html` + `native-app.jsx` + `native.css`; Notes is `notes.jsx` + `notes-editor.jsx` + `notes.css`). When adding or changing screens, treat that prototype as the visual spec.

Current state: **TODOs, labels, office tasks, notes, books, University, Job Study and Product Dev are persisted with SwiftData and synced through CloudKit** (see "Sync" below). Every other feature still comes from `SampleData` and lives in memory (`AppStore`). Settings are in UserDefaults. Editor sheets outside TODOs, Office Tasks, University, Job Study and Product Dev (edit/delete pencils on some rows) are placeholders with no action yet.

## Website

The landing page is the static `docs/` folder (`index.html`, `privacy.html` (the privacy policy the App Store listing links to; keep it true to what the app does), `landing.css`, `landing.js`, icon PNGs, and `screenshot.png`, the hero: a macOS window capture with a transparent background), served by Netlify per `netlify.toml` with no build step; it only redeploys when `docs/` or `netlify.toml` change. Its design comes from `MySelf Landing.html` in the prototype zip. Keep its claims in line with the app (macOS 26, features, Workout "Coming soon"), and re-export the icon variants with `ictool` (see below) when the icon changes.

## Build & run

`xcode-select` points at CommandLineTools on this machine, so prefix `xcodebuild` with `DEVELOPER_DIR`:

```sh
DEVELOPER_DIR=/Applications/Xcode.app/Contents/Developer xcodebuild \
  -project Myself.xcodeproj -scheme Myself -destination 'platform=macOS' build CODE_SIGNING_ALLOWED=NO
```

- That unsigned build runs on a local store only. To test iCloud sync, build signed with the team (`CR9Y3LFYH4`): drop `CODE_SIGNING_ALLOWED=NO` and add `-allowProvisioningUpdates`.
- Debug builds use `MySelf-Debug.store`, not the installed app's `MySelf.store`, and sync to CloudKit's Development environment, so they start with their own data. A Release build shares the installed app's store: running one with a newer schema next to an installed version from before the widget guard (1.4 or earlier) lets that version's app or widgets migrate the store backward, which removes the new tables and leaves the store unable to upgrade.
- Multiplatform target (macOS, iOS/iPadOS, visionOS; deployment targets 26.x/27.0). macOS is the primary design target; guard AppKit/UIKit-only code with `#if os(macOS)`.
- No test target or linter exists yet.
- One Swift package: **SwiftMath** (LaTeX rendering for Notes), declared in `project.pbxproj`. Resolve with `xcodebuild -resolvePackageDependencies` if a build can't find it.
- The project uses file-system-synchronized groups: any `.swift` file under `Myself/` is compiled into the app, under `MySelfWidgets/` into the widget extension, and under `Shared/` into both. Do not edit `project.pbxproj` to add files. `Shared/` must compile in both targets: no `AppStore`, `CloudStore` or AppKit-only code there.
- App icon is the Icon Composer bundle `Myself/AppIcon.icon` (`icon.json` + SVG layers in `Assets/`), wired via `ASSETCATALOG_COMPILER_APPICON_NAME = AppIcon`. Default and dark colours are set per layer with `*-specializations`; the system derives Clear and Tinted (which follows the user's theme colour). Preview any variant with `"/Applications/Xcode.app/Contents/Applications/Icon Composer.app/Contents/Executables/ictool" Myself/AppIcon.icon --export-image --output-file out.png --platform macOS --rendition <Default|Dark|ClearLight|ClearDark|TintedLight|TintedDark> --width 512 --height 512 --scale 1`.
- Build settings: `SWIFT_DEFAULT_ACTOR_ISOLATION = MainActor` in the app (everything is main-actor by default; mark helpers called from non-main closures `nonisolated`; the widget extension keeps the nonisolated default), Swift 5 language mode, approachable concurrency. `MARKETING_VERSION` / `CURRENT_PROJECT_VERSION` are set at project level so the app and the extension always match. The app's `Myself-Info.plist` only adds the `myself://` URL scheme to the generated Info.plist.

## Architecture

- `MyApp.swift` creates the single `AppStore` (`@Observable`), injects it via `.environment(store)`, applies the light/dark override stored in `@AppStorage("appearance")`, and defines the menu commands (Quick Open ⌘K, Go menu with ⌘[ / ⌘] and ⌘1–⌘8).
- `ContentView.swift` is the `NavigationSplitView` shell: sidebar (sections from `Page.groups`, badge counts from `store.count(for:)`), toolbar (back/forward, search), and a switch from `store.page` to a page view.
- `Models/AppStore.swift` holds the `Page` enum (title, subtitle, SF Symbol, sidebar group), all app data, navigation history (`go`/`back`/`forward`), and all mutations. Views call store methods rather than mutating nested arrays directly.
- `Models/SampleData.swift` is the seed ported from the prototype's `store.js`. Dates are relative to today (`Day.offset(n)`) so the app always looks current.
- `Shared/Models.swift` (the structs), `Shared/SchemaModels.swift` (the SwiftData `@Model` types, `cloudSchema`, and model → struct `init(_:)`), `Models/Schema.swift` (the app-only `CloudBacked` struct → model `apply(to:in:)`, and notes' mapping), `Shared/Dates.swift`, `Shared/Theme.swift`, `Shared/SharedStore.swift` (App Group, store URL, `DeepLink`, `WidgetKind`, the Darwin notification widgets post), `Shared/Focus.swift` (`FocusItem`, the Today's focus rule, used by the Dashboard and widgets), `Models/CloudStore.swift` (the store, CloudKit, status, images, synced settings), `Models/FolderImport.swift` (reads the pre-CloudKit JSON folders): see "Sync".
- `Models/Notes.swift`: `NoteCategory`, `Note` (a title plus `[NoteBlock]`), `NoteBlock.Kind` (p, h1–h3, bullet, num, todo, quote, code, math, table, image, hr), `CodeLanguage`, `NoteTable`.
- Notes UI: `Pages/NotesView.swift` (category panel, note list, search, sort, multi-select, drag to a category; fills the detail column instead of using `PageScroll`) and `Pages/NoteEditor.swift` (the block editor). A block shows rendered markdown until clicked, then swaps to `Components/NoteTextView.swift`, an `NSTextView` wrapper that reports Return, Backspace, arrows and Escape to the editor and handles ⌘B/I/E/K and ⇧⌘X/M/H. On iOS it falls back to a plain `TextField`. Rendering helpers: `Support/NoteMarkdown.swift` (inline markdown parser, `MathRenderer` using SwiftMath, which lacks `\operatorname` so it's rewritten to `\mathrm`), `Support/CodeHighlighter.swift` (regex tokenizer and colours), `Support/NoteTypography.swift` (SF Pro at a fixed 15.5 pt body size, with the system's SF Bangla first in its cascade list: Light for regular text, Medium for `**bold**`. Don't bundle a Bengali font that builds conjuncts from positioned parts, like Noto Sans Bengali: the TextKit 1 views (`NoteTextView`, reader mode) scramble them).
- Reader mode (⇧⌘R or the toolbar's book button; `Note.readerMode`, optional so older notes decode; `store.setReaderMode`, which keeps "Date edited"): the editor shows `Components/NoteReaderView.swift` instead of the title and blocks: the whole note built into one read-only, selectable `NSTextView` (`NoteReaderText.build`; code, quotes and dividers use `NSTextBlock`, math and images are attachments, and a click on an image opens the viewer), so a selection can span blocks. The formatting toolbar is hidden, and `focus`, `setBlocks`, block selection and drag selection all refuse while `reading`.
- Table blocks keep GFM table markdown in `text` (`NoteTable` parses it: header, `:-:` alignment row, body rows, and writes it back column-padded). They show as a grid (`NoteTableGrid`) and, when clicked, as source with a live preview, Add Row / Add Column buttons and Tab to the next cell. Pasted `|` lines become a table block; reader mode builds them with `NSTextTable` on macOS.
- Block selection (`selectedBlocks`): Esc in a text or code block selects it, ⌘A selects the block's text and a second ⌘A every block (`NoteKey.selectAll`); Delete removes them, and ⌘C / ⌘X copy or cut them as markdown (`NoteBlock.markdown`). Dragging a text selection out of the block being typed in turns into a block selection (`NoteTextView.onDragOut`), since one text view can't select across blocks. Deleting blocks goes through `store.setNoteBlocks`, which registers undo and writes released image files back on undo.
- Pasting multi-line text into a text block splits it into blocks with `NoteBlock.blocks(fromMarkdown:)` (`NoteTextView.onPasteText` → `NoteEditor.pasteText`). Keep blocks short: SwiftUI takes seconds to lay out one block holding a whole Bengali document, which froze the app; the editor also splits any text block of 20+ lines when a note opens.
- Image blocks keep the file name in `NoteBlock.image` (caption in `text`); the data lives in `NoteImageModel` (synced as a CloudKit asset), and `sync.imageState` hands views a file URL from a cache in Caches (`sync.saveImage`, `imageState`, `store.addNoteImage`). An image is deleted once no note in memory uses it (`releaseImages`: from `editNote` when a block drops its image, and from `deleteNotes`, whose undo writes the data back); duplicated notes share files. Add one from the toolbar, `/image`, the block menus, a drop on the empty block, or by pasting an image into a text block (`NoteTextView.onPasteImage`). `Support/NoteImages.swift` has the cached downsampled preview and `NoteImageViewer` (zoom with ⌘+ ⌘− ⌘0, pinch, double-click), a `WindowGroup(id: NoteImageViewer.windowID, for: String.self)` window on macOS and a sheet elsewhere.
- Open a note on its page with `store.openNote(id)` (Notes, or Book Notes for a reading note), or create one with `store.newNote()` (⌥⌘N).
- Note links (`Pages/NoteLinks.swift`): a link is `[[label|note id]]` in a block's text, parsed by `NoteMarkdown` (`Run.text(…, note:)`). Typing `[[`, ⇧⌘L or the toolbar's `[[ ]]` button opens `NoteLinkPickerView`, a popover that searches notes or creates one; a selection becomes the label. A rendered link's position comes from `NoteLinkRenderer` (a `TextRenderer` that records the runs marked with `NoteLinkAttribute` in `NoteLinkRects`, since `Text` has no per-run hover or tap), which drives the hover preview and the click; reader mode does the same with `myself-note:` link attributes. A click opens the note in its `NoteWindow`. A link whose note was deleted shows grey and does nothing; undoing brings it back. `NoteLinksSection` lists "Linked notes" and "Mentioned in" under the note from `NoteSummary.linkIDs` (`Note.linkIDs`, cached per `updatedAt`). `NoteText.withoutLinkTargets` keeps the IDs out of search, word counts and snippets. Links in code and math blocks and inline code don't count; links in table cells show and count, and work in reader mode, but clicking a table in the editor edits it.
- `Pages/BooksView.swift` (Book Notes; fills the detail column): the library (shelves, or a filtered grid or list) and a book's workspace (`BookPanel` plus `OpenNoteEditor`). A book's reading notes are ordinary `Note`s with `bookID` and `location` set and an empty `categoryID`, so they use the same editor, links, undo and search; `NotesView` filters them out, and the editor hides Pin and Move for them. Book fields go through `store.editBook`, debounced like note typing (`saveUnsavedBooks`). Covers are JPEGs stored as note images (`store.setBookCover`, `NoteImages.bookCover`, `Book.cover`). Book categories (`BookCategory`) are separate from note categories; rename and delete them from a shelf heading's context menu. Change data with `addBook`, `deleteBook` (takes its notes and cover), `addBookNote`, `addBookCategory`, `renameBookCategory`, `deleteBookCategory`.
- Views that only show a note's title, snippet, pin, category or dates read `store.noteSummaries` (`NoteSummary`, edit time kept to the minute), not `store.notes`: it only changes when those do, so typing doesn't redraw the note list, the rail counts or Job Study's linked notes. The editor's `NoteBlockRow` is `Equatable` and compares only what it shows (not `editor`), so typing redraws just the edited block.
- On macOS, double-clicking a note in the list (or Open in New Window in its context menu) opens `Pages/NoteWindow.swift`, a `WindowGroup(id: NoteWindow.id, for: ID.self)` scene; opening the same note again brings its existing window forward. Its "Show in Notes" button brings the main window (`WindowGroup(id: "main")`) forward on that note.
- `Pages/TodoEditorSheet.swift`: the add/edit sheet, opened by setting `store.editingTodo` (`store.newTodo()` for a new one; ⌘N).
- `Pages/OfficeEditorSheet.swift`: the add/edit sheet for an office task (title, notes, reference link, due date; priority is locked to high), opened by setting `store.editingOffice` (`store.newOfficeTask()`; ⇧⌘N). Change tasks with `saveOfficeTask`, `toggleOffice`, `deleteOfficeTask`.
- `Pages/UniversityEditorSheet.swift`: add/edit sheets for classes, assignments, exams and syllabus subjects, opened by setting `store.editingUniversity` (`store.newClass()`, `newAssignment()`, `newExam()`, `newSyllabusSubject()`). Assignments and exams refer to a subject by name; renaming a class renames it on them and on the syllabus. Read the data through `store.university` (`private(set)`) and change it with the store's `save…`/`delete…` methods.
- `Pages/JobStudyView.swift`: subjects panel plus a revision checklist for the selected subject (All / Due / Revised today filters; a topic is due when it wasn't revised in the last `StudyTopic.dueDays` = 7 days). Topics drag to reorder (dropped on a row it lands above it, on "Add topic…" at the end; `moveStudyTopic`) and link notes (`noteIDs`) through a search popover; a linked note opens in its own `NoteWindow`, and "New note" creates it in a "Job Study" note category (`store.addTopicNote`). The subject sheet (name, colour) reuses `EditorForm`/`SwatchPicker` from `UniversityEditorSheet.swift`. Change data with `saveStudySubject`, `deleteStudySubject`, `reviseTopic`, `adjustRevisions`, `addStudyTopic`, `renameStudyTopic`, `deleteStudyTopic`, `toggleTopicNote`.
- `Pages/ProductsView.swift`: project tabs (+ adds one), header with edit/delete, and the board. Clicking a card opens its sheet; cards drag between columns (dropped on a card it lands above it, on the column at the bottom) and have a Move To context menu. Project and card sheets live in the same file. Change data with `saveProduct`, `deleteProduct` (takes its cards too), `newCard`, `saveCard`, `deleteCard`, `moveCard(_:to:before:)`; read a column with `store.cards(of:in:)`, and set `store.selectedProduct` to open a board.
- `Support/Dates.swift`: `Day` helpers (`fromToday`, `sessions(on:count:)`, which generates class dates from weekdays), `DueMeta` (the "Today / Tomorrow / 2d overdue" badge text and tone), `Weekday`, `ClockTime`.
- `Support/Theme.swift`: `Palette` holds the design tokens from `native.css` as adaptive light/dark colors, built with `Color.dynamic(light:dark:)`. Use `Palette.*` and `Color.accentColor` instead of hard-coded colors. User-chosen colors (labels, classes, projects) are stored as `UInt32` hex in the models.
- `Components/Components.swift` contains the shared design-system pieces: `PageScroll` (page padding/max width; it also publishes `pageWidth` into the environment), `AdaptiveColumns` (two columns when wide, stacked when narrow), `Card`, `StatTile`, `Badge`/`PriorityBadge`/`DueBadge`/`LabelChip`, `CheckCircle`, `ProgressBar`, `Donut`, `ColorTabs`, `RowActions` (hover-revealed edit/delete), `FlowLayout`, `ListRow`, and `HoverState`/`HoverOpacity`/`HoverFill`. Keep row hover in a `HoverState`, not a `@State` Bool: scrolling moves rows under the pointer, and a `@State` hover redraws each whole row it crosses. Put shadows on a background shape, never on a container (`cardBackground` does): a shadow on content renders all of it offscreen again on every change.
- Menu commands that read the store live in their own views (`NewItemCommands`, `GoCommands` in `MyApp.swift`); if `MyApp.body` reads the store, every page switch rebuilds every scene and the main menu.
- `Pages/` has one view per sidebar page, plus `QuickOpenView` (the ⌘K palette) and `SettingsView` (the ⌘, window on macOS, a sheet elsewhere; tabs General / Features / iCloud). Open it from code with `store.openSettings(tab)`.
- `Support/SearchShortcut.swift` (macOS): the system-wide "Search MySelf" shortcut (default ⌥⌘K, saved as `searchShortcut` in UserDefaults, per Mac). It's a Carbon hot key, so no Accessibility permission is needed; pressing it shows `QuickOpenView` in a floating, non-activating `SearchPanel` over the front app (like Spotlight), and MySelf only comes forward when a result is picked (`SearchShortcut.open`). `ShortcutRecorder` is its Settings › General control.
- `Support/MenuBarMenu.swift` (macOS): the menu bar icon (a `MenuBarExtra` in `MyApp` drawn from the `MenuBarIcon` template asset, the app icon's two circles; toggled by `PrefKey.menuBarIcon` in Settings › General). Its menu has New Todo / Office Task / Note, Search (the `SearchShortcut` panel), Go To a page, Open, Settings and Quit; actions bring the main window forward with `SearchShortcut.shared.showMainWindow()`. Hide disabled features here too.
- `Support/UpdateChecker.swift` (macOS): checks the latest GitHub release (the redirect from `github.com/Ok9xNirab/myself/releases/latest` to its tag page, not the rate-limited REST API) against `CFBundleShortVersionString` at launch (once a day, `PrefKey.checkForUpdates`) and from MySelf › Check for Updates…, and shows an `NSAlert` linking the DMG. There's no auto-install. Bump `MARKETING_VERSION` and tag releases `v<version>` for it to work. It's compiled only into the DMG (`scripts/make-dmg.sh` sets the `DIRECT_DISTRIBUTION` condition and the outgoing-network entitlement); App Store builds, archived from Xcode, have neither, since App Review rejects in-app update prompts. Guard any other DMG-only code with `#if DIRECT_DISTRIBUTION`.
- `Support/LegacyImport.swift` (macOS): the bundle ID is `com.quorrelapps.myself`; 1.3.1 and earlier used `com.ok9xnirab.myself`, whose sandbox container this app can't open by itself. On a fresh install `ContentView` asks once (`store.shouldOfferLegacyImport`, `PrefKey.legacyImportOffered`), and Settings › General › Data has Import…: an `NSOpenPanel` opened on the old container grants access, and `store.importLegacyData` reads its records through `FolderImport` and copies the old preferences (not the sync ones). If the old app synced through an iCloud Drive folder, it opens Settings › iCloud, where that folder can be imported.
- `Support/Preferences.swift`: `PrefKey` (all `@AppStorage` keys), `SidebarStyle`, `RowDensity` (read by `ListRow` via `\.rowDensity`), and `appPreferences(...)`, which every scene applies. There's no accent setting: `Color.accentColor` follows the Mac's accent (the `AccentColor` asset when it's set to multicolour).

## Feature visibility

University, Office Tasks, Job Study, Product Dev, Workout, Notes and Book Notes can be turned off in Settings › Features (`store.isEnabled`, `store.setEnabled`, persisted as `disabledFeatures` in UserDefaults). A disabled feature must be hidden everywhere: sidebar (`Page.groups(store.enabledPages)`), Dashboard cards and tiles, Quick Open, the Go menu, and the note link picker and "Mentioned in" (`store.isNoteVisible`). Its data stays in the store. Dashboard and TODOs can't be turned off. `Page.isAvailable` drops "Coming soon" pages (Workout) from App Store builds entirely, since App Review rejects placeholder features: `isEnabled` is false for them and Settings › Features doesn't list them. They still show in DMG builds (`DIRECT_DISTRIBUTION`). When adding UI that surfaces a feature's data outside its own page, guard it with `store.isEnabled(_:)`. Feature visibility and appearance can also sync (see below).

## Sync

Data lives in a **SwiftData store mirrored to the user's private CloudKit database** (container `iCloud.com.quorrelapps.myself`), so every device on the same Apple Account syncs, with no folder to pick. Appearance and feature visibility sync through `NSUbiquitousKeyValueStore` (`readSettings`/`writeSettings`, `pushSettings`/`pullSettings`). Entitlements are in `Myself.entitlements` (macOS) and `Myself-iOS.entitlements`, outside `Myself/` so the synced group doesn't bundle them: CloudKit, key-value store, push (`aps-environment`) and the App Group `CR9Y3LFYH4.com.quorrelapps.myself` (`group.com.quorrelapps.myself` on iOS), whose container holds the store so widgets can read it later.

- **Models now, screens later**: `AppStore` still holds plain structs (`Todo`, `Note`, …) and the views read those. `Schema.swift` defines one `@Model` per synced struct (`TodoModel`, `NoteModel`, `KanbanCardModel`, … with real fields and relationships, queryable with `#Predicate`); each struct converts with `init(_ model:)` and writes itself with `apply(to:in:)`. Screens or widgets can move to `@Query` one at a time without schema changes. Never assign `store.todos`/`labels`/`office`/`notes`/`noteCategories`/`university`/`jobStudy`/`products`/`cards` directly; they're `private(set)`, and the store's methods save through `sync.save` / `sync.delete`.
- **CloudKit schema rules**: every attribute has a default or is optional, every relationship is optional with an inverse, no `.unique`, no `.deny`. Enums are stored as raw strings, colours as `Int`, a note's blocks as JSON in `NoteModel.blocksData` (external storage), topic order as an `order` field (relationships are unordered). **After the schema is deployed to production in the CloudKit Console, only add fields or models: never rename, retype or remove one.** Deploy the schema before each release that adds any.
- `recordID` is the struct's `id`; it isn't unique in the store. `CloudStore.fetchAll` merges copies with the same `recordID` on every load: the newest `updatedAt` wins (ties broken by the synced random `copyID`, so every device keeps the same copy), and `absorb` moves the loser's relationships to the winner. This is what keeps the fixed-ID defaults and repeated imports from duplicating.
- `reloadSynced()` runs inside `sync.scan`, which starts a fresh `ModelContext` so it sees what CloudKit imported. It runs after CloudKit import events (`NSPersistentCloudKitContainer.eventChangedNotification`, debounced), on key-value store changes, and when the app becomes active. Every store mutation saves at once; `sync.batch { }` groups many writes into one save (Reset, imports).
- Note typing goes through `store.editNote`, which updates memory at once and saves once typing pauses for 2 s, or every 10 s during long runs of typing (`SaveDebounce`, `saveUnsavedNotes`), and when the app leaves the foreground or quits (`saveTypedText`). A reload keeps the in-memory copy of notes with unsaved edits. Pin and move bump `updatedAt` but not `editedAt` ("Date edited").
- `sync.status` (`.local`, `.noAccount`, `.syncing`, `.upToDate`, `.failed`) comes from CloudKit events and the account status; the sidebar footer and Settings › iCloud show it. Turning sync off or on rebuilds the container on the same store file. Builds without the iCloud entitlement (`CODE_SIGNING_ALLOWED=NO`) run on the local store only (`CloudStore.canUseCloudKit`), and use the app's Application Support when the App Group isn't writable.
- **Importing pre-CloudKit data** (`FolderImport`): the old layout (`todos/<id>.json`, `labels/`, …, `noteimages/`, `university/notes.json`) is read through the structs' `Codable`, the newest copy per ID wins, and a record already in the store is only replaced by a newer one; folders are never changed. The app's old local folder is imported once automatically (`PrefKey.importedLocalFolder`), Settings › iCloud › Import a sync folder takes an iCloud Drive folder, and `LegacyImport` reads the old `com.ok9xnirab.myself` container.
- Debug builds have a self-test of this layer: run `Myself.app/Contents/MacOS/Myself -selfTest` (`Support/SelfTest.swift`). It uses a temporary store, checks every type's round trip, edits, reordering, duplicate merging, folder import and images, prints `SELFTEST PASSED` or the failures, and quits. Run it after changing the schema or the mapping.
- `NoteModel.bookID` and `BookModel.categoryID` are plain string fields, not relationships, so a reading note that CloudKit delivers before its book can't briefly appear among the ordinary notes.
- New installs start with no todos, office tasks, notes, books, University, Job Study or Product Dev data. The default labels and note categories use fixed IDs (`l1`…`l6`, `nc1`…`nc4`) with `updatedAt = .distantPast`, so two devices seeding them converge on one copy (the merge keeps the newest) and can't overwrite renames. TODOs and Product Dev keep separate label sets in the same `LabelModel` table, told apart by `TaskLabel.scope` (nil means TODO). Read them with `store.labels` / `store.productLabels` (`allLabels` holds both); `LabelPicker` (in `TodoEditorSheet.swift`) is the shared chip picker with New/Delete Label. Product Dev's defaults (`pl1`…`pl6`) are seeded once per Mac, and `moveCardsToProductLabels()` runs after every reload to give cards that still point at TODO labels a Product Dev copy (ID `p-<original>`). Settings › Reset loads the sample todos, office tasks, notes, books, University, Job Study and Product Dev data into the store (and so onto every synced device).

## Domain rules carried over from the design

- Office tasks and university assignments are always high priority (shown as "High · locked").
- Dashboard "Today's focus" lists todos and office tasks that are due today or overdue, plus assignments due by tomorrow.
- Job Study: ticking a topic adds one revision dated today, and un-ticking it the same day undoes that (`previousRevised` restores the earlier date). The ± stepper corrects the count; + dates it today, and taking it to 0 clears the date. The sidebar badge counts due topics.
- Workout: a program's completed weeks always form a prefix, and weeks after the current one are locked. Programs without `weeks` show a simple counter out of 8 weeks.
- Product Dev boards always have the columns Backlog / In Progress / Review / Done (`KanbanStatus`). The sidebar count and the dashboard both read `.inProgress`. A card in Done shows its date plainly instead of as overdue.

## Widgets

`MySelfWidgets/` is a macOS WidgetKit extension (`com.quorrelapps.myself.widgets`, embedded in the app's PlugIns, sandboxed with the same App Group) with ten widgets; the visual spec is `MySelf Widgets.html` in the prototype zip. One file per widget in `Widgets/`; `Components/` holds `Caption`, `Chip`/`DueChip`, `ProgressBar`, `Ring`, `WidgetStyle` (fonts, colours, `Hairline`, empty and feature-off states) and `WidgetPreviewCard` (dark previews).

- `Data/WidgetStore.swift` opens the app's store in the App Group with `cloudKitDatabase: .none` (only the app mirrors to CloudKit) and never creates or migrates it: it only opens the store once the app has opened it with the same schema (`SharedStore.isStoreCurrent`, set by `markStoreOpened`), so after a schema change widgets show their empty states until the app is launched. It reads the newest copy per `recordID`, as the app's merge would. Intents write to every copy, bump `updatedAt`, and post `SharedStore.didChangeNotification`; the app reloads on it (`WidgetRefresh.observeWidgetWrites`).
- `Data/WidgetSnapshot.swift` derives everything from the structs with an explicit `now` (the timeline entry's date): use `Day.between(now, date)`, not `Day.fromToday`, in widget code. `WidgetSnapshot.sample` mirrors the mock for placeholders, the gallery and previews.
- Timelines: entries at now, each class start for the rest of the day, and midnight, `.atEnd`; 30 minutes when the store can't be read.
- The app reloads timelines (`Support/WidgetRefresh.swift`, debounced) after any save that touches todos, office, University or Job Study models, after CloudKit imports, and when Settings › Features changes. The app copies disabled features into the App Group defaults (`SharedStore.disabledFeaturesKey`) and widgets show a "turned off" state for them.
- Deep links: `myself://dashboard|todos|todos/new|office|university|jobstudy|notes|notes/new` (`DeepLink`, handled by `AppStore.open` from `ContentView.onOpenURL`; the main window handles them, never a note or image window).
- Interactive: `ToggleTaskIntent` (Today's focus) and `IncrementRevisionIntent` (Revise next, same rule as the + stepper). Configurable: `SyllabusConfiguration`, `ReviseConfiguration`.
